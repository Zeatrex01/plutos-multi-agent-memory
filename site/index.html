Why it exists

Three AIs, three blank slates.

Every tool keeps its own chat, its own guess about the project and its own "may I?" prompt. The one you are not looking at is the one that is stuck.

Without a shared record

Claude
Codex
Cursor
  • You explain the project again, every session.
  • Two agents take the same task, one undoes the other.
  • A note from last week is handed over as a fact after the code changed.
  • “Done” arrives with no test run behind it.

With PLUT_OS

  • Each session opens with one short brief: the board, the decisions and the facts that still hold.
  • Tasks are claimed on one board in your repo, with race-tested writes.
  • Every fact carries the line it came from; when that line changes, the fact is quarantined.
  • A “done” goes back when the tests did not run or a test was edited in the same fix.
  • Questions for you land in one queue, sealed to what was asked.
How a session goes

From a blank slate to a record the next AI reads.

PLUT_OS does not drive your AIs. They talk to it through a local MCP server and plain files in your repository.

01 · SESSION_START

The AI gets the brief

Where the work stopped, the decisions in force and the facts that still match their source. About 728 tokens on a fresh project.

02 · BOARD

It claims a task

On the shared board, with the check that will show it is finished. Another AI sees the claim and picks something else.

03 · PLUTOS_ASK

It asks you, once

A decision it should not make alone becomes a card in the dashboard, with the options it offers. Pending is never approval.

04 · SESSION_END

It leaves a record

Decisions with their reasons, facts with the exact line they came from, and what was not checked. The next AI, whichever tool it is, starts from here.

Memory that notices

When the code changes, the old fact stops being true.

A fact is stored with the exact line it was read from. Change that line and the fact is quarantined: not deleted, not forgotten, just no longer handed over as true.

What is inside

Small, local, and checkable.

🧠

Decision memory

Every decision has an id; reversing one names the one it replaces. plutos memory find searches decisions, facts and sessions in English and Turkish.

🗂️

Shared board

Atomic, race-tested writes and per-entry revision checks. Assign a task to another AI and it arrives in that AI's next brief.

✋

One approval queue

Sealed to the exact content, expiring, run once. plutos approve needs an interactive terminal, so a script cannot answer its own ticket.

✅

False-done checks

The claim check sends a “done” back once; plutos check lists what the records name that the repository does not show.

🔌

Every AI tool

Claude Code, Codex, Cursor, Gemini CLI, Antigravity, Windsurf, Zed and VS Code Copilot connect through MCP, each with the file it reads.

🧹

No trash left behind

plutos audit lists what older setups left in a project and what fixes each; leftovers are moved, never deleted.

Unzip and run. Nothing to install.

The dashboard opens at http://localhost:3040. From the latest release:

Unzip, double-click PLUT_OS.exe. Download for Windows

PLUT_OS

macOS · any system with Node.js 22+

Lite

Unzip, run ./start-plutos.sh or START_PLUT_OS.bat. Download lite

The AI tools you connect start PLUT_OS's MCP server with Node.js, so they still need Node.js 22+ on the machine. Settings → Updates in the dashboard says when a newer release is out.

Or from source

cd plutos-multi-agent-memory
npm ci --omit=dev
node dashboard.mjs --open

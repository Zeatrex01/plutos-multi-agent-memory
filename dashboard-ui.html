    Guide

    How PLUT_OS works, from adding a project to following the work, and the words it uses.

    Getting started

    1. Add the project on Projects. PLUT_OS reads the folder; nothing in it changes.
    2. Install the project kit, also on Projects. It adds the shared board, memory and rules files your AIs use (listed below); your own files are not touched.
    3. Connect an AI tool: Projects → Connect an AI. Each tool reads a different settings file; PLUT_OS writes the one yours reads. Reload the tool, and the top bar shows AI: connected.
    4. Let your AI read the project. Tell it: Read this project and write its map. Every later session starts from that map.
    5. Give the first task on the Board with Assign a task, and follow it on Home.

    Optional: five questions in Setup questions that recommend tools.

    Who does what

    You are the boss. Your AI tools (Claude Code, Codex, Cursor, Gemini…) do the work, and each one manages only its own helpers. PLUT_OS never commands an AI: it gives them a shared place to work and shows you what is going on. Three shared files carry it:

    BOARD.md
    The tasks: To do (with who it is for), In progress (someone claimed it), Done (with where the result is), Blocked (with what it waits on). It is the Board page.
    AGENT_BOARD.md
    Notes and findings from the AIs' helpers. It is the Agent board tab on the Board.
    ROSTER.md
    Every AI and helper on the project, and whose it is. To use another AI's helper, an AI leaves a suggestion on the board; that helper's owner decides.

    Where things are

    Work
    Home: what needs you and the next step. Board: give and follow tasks. Shared Table: one job answered by several departments.
    Knowledge
    Report: what happened and what your AIs recorded. Research: research with saved sources. Code map, Documents, Dependency graph: maps of the project.
    Setup
    Projects (with Connect an AI and the extra tools your AI can set up), Setup questions, Settings and this Guide.

    Some pages are off until you need them: turn them on in Settings → Pages in the menu. Nothing is uninstalled when a page is off.

    The words PLUT_OS uses

    Project kit
    The shared files PLUT_OS adds to a project so your AIs share a board, a memory and rules.
    Watch-only
    A project that is added but has no kit yet: PLUT_OS reads it and keeps its own records outside it.
    AI link (MCP)
    How an AI tool talks to PLUT_OS. The top bar says whether one is connected, set up but waiting, or not set up; click it to see or fix it.
    Session
    One stretch of work by one AI, from opening the project to recording what it did.
    Session memory
    What an AI records when it finishes: what it did, decided and learned, with sources. The next AI starts from it; Report shows it, and marks what nobody checked.
    Approval
    A question an AI asks before something it may not do alone. It appears at the top of every page until you answer.
    Result check
    Whether someone recorded that finished work was checked, and where the evidence is.
    For your AIs: the PLUT_OS tools they use

    The dashboard is your side; your AIs reach the same things through PLUT_OS's MCP server once connected. The main ones:

    session_start / session_end
    Read the brief at the start of a session; record what was done, decided and learned at the end.
    board_read / board_update
    Read and update either board without editing the files by hand.
    plutos_ask
    Ask you a question and wait for the answer (it appears as an approval).
    plutos_context_for_task
    Which files to open first for a task.
    agent_register / roster_read
    Register a helper; see who exists and whose they are.
    status_report / project_snapshot
    The same report as the Report page; one file another AI can pick the work up from.
    What the project kit adds to a project 
    Project-Root/
 ┣ AGENTS.md              shared rules for every AI
 ┣ PLUT_OS.bat            double-click: opens this dashboard on this project
 ┣ .plutos/               PLUT_OS's own state for the project
 ┣ docs/ai/               the generated code map
 ┗ docs/handoff/
   ┣ BOARD.md             the tasks
   ┣ AGENT_BOARD.md       the helpers' notes
   ┣ ROSTER.md            who is on the project
   ┗ results/             documents the AIs produce

    Existing files are never overwritten. Connecting an AI is a separate step. The full guide is docs/GUIDE.md.

    Add a project

    PLUT_OS will read the folder and keep its generated map and tasks in the local Hub. It will not add AGENTS.md, .plutos, MCP files, editor settings, launchers, or .gitignore entries to the project.

# First-glance checks (F1-F15)

Checks measured on the render (DOM text, computed styles, the screenshot), so an agent cannot pass them by reading
its own code. From the research report "İlk bakış tasarım ilkeleri" (2026-11-05) and the owner's blind picks. Labels:
measured / practice / opinion; a number marked opinion is an operational choice, not a sourced figure.

| # | Rule | How to check it on a render | Label |
|---|---|---|---|
| F1 | The first heading names the screen and its state in plain words, at the top, in the users' language | Read the first heading in the screenshot; it contains the screen's object and state ("Siparişin yolda, 14:20"), not a brand slogan | practice (Krug; F-pattern measured) |
| F2 | All UI copy is in the users' locale; `lang` matches it | Read `document.documentElement.lang` and sample the visible strings; no English string on a screen for Turkish users | opinion (inference from plain-language evidence; owner pairs) |
| F3 | Word budget: a single-purpose app screen shows 110 visible words or fewer above the fold (excluding navigation chrome); flag any screen over the project's own accepted median | Count `innerText` words inside the viewport at 375 and 1280 px | measured basis (Weinreich 111-word figure); threshold opinion |
| F4 | A halving pass: the final copy is at least about 30% shorter than the first draft, and each removed line passes "would losing it change the next action?" | Diff word counts of the first and final renders; list the cut lines | measured (Morkes & Nielsen 1997, concise +58%, old) |
| F5 | No promotional adjectives and no helper line that restates its control | Grep visible text against a word list ("powerful", "seamless", "kolayca", "harika"); compare each helper line with its label | measured (objective tone +27%, old); practice |
| F6 | Levels, not a receipt: the first thing below the title is what to act on (a framed alert or the main object); key figures are large; the features the user may want next (navigation, filters, search, create) are visible and labelled; no eyebrow labels; summary tiles never come before the thing to act on | In the screenshot: what sits right under the title; whether the key numbers are the largest text after the title; whether navigation/filters/search/create are visible without scrolling; whether every row looks the same | opinion (owner picks rounds 1 and 3, 2026-11-05; skill consensus on eyebrows) |
| F7 | Blur test: with the screenshot blurred about 10 px, or downscaled to about 1/8, the largest and highest-contrast region is the intended main thing | Blur the PNG and mark the top-contrast region; compare it with the intended focal element | practice (NN/g squint test); blur size opinion |
| F8 | Exactly one primary-styled action per view | Count buttons with filled or accent styles in computed CSS; expect 1 | practice (GOV.UK, NN/g, Apple HIG) |
| F9 | Contrast ceiling: three emphasis levels or fewer; no second high-contrast region (dark bar, saturated block) competing with the focal one; red only for warnings or destructive actions | In the blurred render, count regions whose luminance differs strongly from the page; check where red or warm hues appear | practice (NN/g ≤3 contrast variations, red for warnings) |
| F10 | At most one type-size jump to the top tier, two large elements, three type sizes | List computed `font-size` values of visible text; count sizes and elements in the top tier | practice (NN/g) |
| F11 | One framed region: the main content sits in one surface set apart by background or elevation; other content is grouped by spacing; no card inside a card | Count visible elements whose background, border or shadow differs from the page; expect one major container and nesting of 1 | practice (NN/g common region, clutter caveat); "soft" styling opinion |
| F12 | No more than four peer choices in the primary decision area, or groups of four or fewer under headings; rare options one tap away | Count sibling interactive elements in the main region | practice (Cowan-based heuristic, NN/g progressive disclosure) |
| F13 | Prototypical layout: the title at the top, the primary action where the platform puts it (lower half on phones), a familiar pattern for the screen type | Compare positions in the screenshot with the platform convention for that screen | measured (Tuch 2012, appeal) |
| F14 | Softness never removes accessibility: text 4.5:1, visible labels (not placeholders), no pale disabled button without a stated reason | axe or WAVE scan; grep for `placeholder` without `label`; check disabled buttons | measured (WebAIM, NN/g, GOV.UK) |
| F15 | A fresh-eye 5-second test: a separate agent sees only the screenshot and answers "what is this, what happens if you press the most prominent control, what did you see first?"; it passes if all three match the intent | Spawn a critic with no code or brief; compare its answers with the intended purpose, action and focal element | practice (5-second test); one AI pass is about one evaluator, measured weak |
